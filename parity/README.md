# Parity cases

These files hold the cases that the Python prompt engine (`backend/app/prompting/`) and
its TypeScript twin (`frontend/src/engine/`) must answer identically. A case is
`{"fn", "name", "input", "expected"}`: `fn` names a function, `input` is the object of its
named arguments, `expected` is what it returns. pytest and vitest read the same files.

`expected` is generated by the Python, never written by hand. After changing the Python,
regenerate it from `backend/` with `python -m tests.parity_cases` and read the diff: that
is the change in behaviour, and it fails the TypeScript side until the twin follows.
Never edit an `expected` to make a test pass; fix the code that disagrees.

Each `fn` is registered on both sides, in `FUNCTIONS` (`backend/tests/parity_cases.py`) and in
`frontend/src/engine/parity.test.ts`; a test fails for a function with no case or a case
with no function. Characters that cannot be told apart in a file (controls, spaces other
than " ", zero-width marks, the byte order mark) are written as `\uXXXX` escapes.

`fuzz.json` is the one file whose inputs nobody wrote. `python -m tests.parity_fuzz`
draws them from a fixed seed (`backend/tests/parity_fuzz.py`) and `python -m tests.parity_cases`
leaves them alone, rewriting only `expected`, as for every file. A divergence that it shows
is a defect of one engine: fix that engine, and put the reduced case in the file of its
family. Never remove a case from `fuzz.json` to make a test pass; to change what it draws,
change the generator and run it again. The file stays under 500 KB, so the counts in the
generator are chosen for that.

Random text seldom reaches a budget, a cut or a macro, so the generator makes some cases do
(a context too small for the history, a fact too long for its budget, `{{original}}` in a
card prompt, a name made of `$&`), and `test_parity.py` counts that the file holds enough of
each (`MINIMUMS` in the generator). To look further than the file does, write another seed
beside the others, run both suites, which read every file here, and delete it:

    python -m tests.parity_fuzz --seed 7 --scale 4 --out ../parity/hunt.json

`parity/hunt*.json` is ignored by git.

What a case file cannot hold is tested directly, on both sides, in `frontend/src/engine/llmJson.test.ts`
and `backend/tests/test_llm_json.py`: NaN and the infinities, lone surrogates, integers past 2^53,
and replies nested 100,000 deep.
